# ADR-0021: Remove Spec Kit from the delivery baseline

Status: Accepted
Date: 2026-10-06
Supersedes: the Spec Kit part of ADR-0018

## Context

ADR-0018 adopted GitHub Spec Kit 1.0.5 for living scope and intent, together with an OpenCode
integration (`.opencode/commands/speckit.*`, `.specify/`) and a reusable Spec Kit bundle under
`tooling/spec-kit/typescript-engineering-baseline/` (preset, verification extension, and gated
workflow). The repository owner has decided that projects will no longer use Spec Kit.

## Decision

Remove Spec Kit from the baseline:

- Delete `.specify/`, `.opencode/commands/speckit.*`, `tooling/spec-kit/`, the bundle validation
  and lifecycle code in `tooling/engineering-baseline/src/bundle/`, and `pnpm speckit:check`.
- Drop `specKitVersion` from `engineering-baseline.config.json` and its schemas.
- Withdraw FR-013 and SC-005 to SC-007 from `specs/001-engineering-baseline/spec.md`. Their
  identifiers are not reused.

Everything else in ADR-0018 and ADR-0019 stays in force: the living `spec.md` with stable
`FR-###`/`SC-###` identifiers, Full/Standard/Lightweight lanes, Gate 1 and Gate 2 records,
Cucumber/Gherkin as the outer acceptance loop, Vitest TDD as the inner loop, generated
traceability, and contract-first external interfaces. These are enforced by the repository's own
tooling (`pnpm baseline:verify`, `pnpm baseline:check`) and do not depend on Spec Kit.

## Consequences

Specifications, plans, and tasks under `specs/<feature>/` are written and maintained directly by
contributors and AI coding agents following the agent skills and `.github/copilot-instructions.md`,
not generated by `/speckit.*` commands. There is no distributable bundle; projects adopt the baseline
by copying its documents, skills, configuration, and scripts. Planning documents written for the
0.1.0 feature keep their Spec Kit passages as history, marked as such.

## Alternatives considered

- Keep Spec Kit but stop requiring it: rejected because an unused, pinned toolchain still has to be
  maintained and verified in CI.
- Remove the whole spec-driven process (as on `feat/engineering-standards`): out of scope here; the
  BDD, TDD, and contract-first parts are kept until a separate decision says otherwise.

## Follow-up work

- Resolve the ADR numbering collision with `feat/engineering-standards` (ADR-0018 to ADR-0020) when
  the two lines are merged. This ADR uses 0021 so it collides with neither.
